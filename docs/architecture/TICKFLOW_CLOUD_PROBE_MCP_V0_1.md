# TickFlow AWS isolated probe → read-only MCP evidence V0.1

**Scope:** isolated TickFlow AWS Premium smoke probe **only**, not production A-share ingestion. This is independent of the existing US OpenD LiveFeed and the Eastmoney/Tencent A-share cloud source.

The opt-in existing `ops/aws/run_tickflow_premium_probe.sh` now writes an atomic, allowlisted, **sanitized** JSON cache to `/opt/stock-razor-tickflow-premium-probe/last-sanitized-probe.json` after a successful probe validation. The file contains only probe time, exact source SHA, operation types, bounded row counts/latencies, fixed-status schema/freshness/closure fields and blocked admission. It contains **no API key, account identity, provider payload or raw error**. No new network calls, provider subscriptions, paid probes, AWS deployments, trading, or service restarts are introduced by this PR.

`get_tickflow_probe_health()` is a read-only MCP tool that reads this local file, checks its size/schema/age (default one hour) and returns only allowlisted fields. It never calls the TickFlow SDK. A fresh probe returns `status=PROBE_ONLY`, `ok=true` to indicate readable evidence **only**; it always returns `production_tickflow_feed=false`, `tickflow_to_radar_e2e=NOT_VERIFIED`, `data_admission=BLOCKED`, `RADAR_ADMISSION=BLOCKED`, `LIVE_TRADE=NO`. Missing, stale or invalid caches fail closed. The currently running MCP is not updated until an independently approved CI/deploy.

**Not yet supported:** `get_tickflow_bars` (no verified durable bar cache), TickFlow WebSocket continuity, source arbitration, TickFlow live subscription management. Those require separate data quality / entitlement and E2E gates.

**Deployment caveat:** The cache is only generated by a future explicitly authorized Premium probe run. Before claiming native ChatGPT access, verify the MCP service has filesystem read access to the cache and has deployed the matching exact SHA; a CI merge alone does not update AWS.
