## Two independently observed endpoints

**AWS Tokyo:** `Audit TickFlow AWS Research Feed and MCP (Read Only)` GitHub Actions workflow `.github/workflows/audit-cn-tickflow-live-research.yml`, with protected-main-only GitHub AWS OIDC + fixed private SSM target. UTC cron `0,30 2-7 * * 1-5` nominal 10:00, 10:30, …, 15:30 Shanghai on weekdays. It reads already-collected private cache and read-only MCP **twice, 65 seconds apart**; sequence change and bounded age; records the four held ETFs across 1m/5m/15m/60m/1d plus provider identity and sanitized independent historical price comparisons. AWS public Actions logs only fixed-enum/bucket sanitized status; OHLC or account credentials are never logged. Missing Klines fail admission; vendor-float acceptance is research only, not strict exchange finality.

**Desktop:** Windows Task Scheduler task `STOCK_RAZOR_TickFlow_Desktop_30m_ReadOnly` is enabled and runs every 30 minutes from 00:00 local time **only while the interactive user is signed in and the device is awake, online, and on AC power**. The observed task uses `StartWhenAvailable=false` and `IgnoreNew`: missed intervals are not replayed and overlapping runs are skipped. Wrapper `%LOCALAPPDATA%\StockRazor\TickFlowHalfHour\half_hour_check.ps1` checks the Shanghai weekday market window before making calls; outside that window it exits successfully without calling TickFlow or appending an audit record. Thus a Task Scheduler result of `0` alone does not prove a data read; inspect the latest JSONL record. The approved research matrix is four holdings × 1m/5m/15m/60m/D1 (20 bounded reads per complete worker poll), SDK `0.1.25`, and Windows Credential Manager key; no secret leaves the user account. As verified 2026-10-15, the installed audit script matches the main-branch script and the credential target exists; no key value was read. Sanitized local JSONL `%LOCALAPPDATA%\StockRazor\TickFlowHalfHour\audit-sanitized.jsonl`; max ~1MB rotation. Strict OHLC and research-only vendor-float statuses are separate; no provider prices are logged. Device off means **no local measurement**, and cloud must explicitly label desktop `OFFLINE_OR_NOT_OBSERVED` rather than falsely claiming both endpoints checked.

**Latest eligible desktop evidence (2026-10-15 16:30 JST):** that evidence predates the four-holding matrix change. New runs must report 20 bounded reads; prior two-holding evidence is not reused as complete coverage. No result proves exchange finality or trading admission.

## Evaluation/alerts/limitations
- Two identical ETF+timeframe sets, poll timestamps recorded independently. Compare completed due-label counts, contiguous Shanghai 5m/15m/60m grids, normalized strict/tolerant OHLC buckets, observed source SHA and sequence. No assumption of exchange finality, broker permission or availability at exactly cron minute.
- Existing GitHub Actions failure email/status is an audit-execution alert; it is **not a guarantee** of mobile notification. A green GH run means the AWS audit ran successfully, **not** that TickFlow real-time admission passed. Both-end correlation remains manual until explicit authorized secure local summary uploader is built; do not expose desktop logs publicly or add GitHub write permissions.
- Weekday **exchange holidays** are not verified by this monitor; closed-market windows fail closed. No holiday false PASS. Periods outside the above schedule are `NOT_OBSERVED`; historical-only samples are not live evidence.
- Max 12 AWS audits × roughly 65s each per weekday. Windows runs ~12 times in that time window (some skipped due to lunch windows). Cloud cache probes **do not** produce new paid TickFlow reads; Windows uses bounded existing monthly plan only.
- `SOURCE_ARBITER_ADMISSION=BLOCKED`, `RADAR_ADMISSION=BLOCKED`, `PAPER_AUTO_READY=NO`, `LIVE_TRADE=NO`, `TRADE_EXECUTION=NO`.
